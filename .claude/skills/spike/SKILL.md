# Spike for issue #$ARGUMENTS

Follow CLAUDE.md. A spike produces a decision. Spike code never becomes production code.

1. `gh issue view $ARGUMENTS`. Restate the question, the good-enough threshold, the budget and the stop conditions.
2. Branch `wi/$ARGUMENTS-<short-slug>`. Put all code under `experiments/$ARGUMENTS-<short-slug>/`
   (create the folder if needed). Nothing in src/ may reference it, and don't copy the
   governed/bounded/opt-in multi-flag CLI pattern from the WI-0155 tools.
3. Measure against the threshold. Outputs are aggregate numbers only: no photos, frames, crops,
   embeddings, names, private paths or catalogue rows, and never open media files.
   Nothing is sent to third-party services.
4. **Hard stop** when the threshold is met, the budget is spent, or two attempts at the same problem
   have failed. Don't keep tuning.
5. Write the findings note: the question, the method, the numbers (before/after if anything changed),
   the limits, and exactly one recommendation: **adopt** (draft a build issue), **drop**, or a
   **new spike** with a new threshold.
6. Post it as a comment on the issue (`gh issue comment`), or as the PR body if the experiment code is
   worth keeping in experiments/. End the comment with a line `---` and then
   `Generated by [Claude Code](https://claude.ai/code)`.
7. Stop.
